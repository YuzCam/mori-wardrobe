# 沐衣架构

界面采用手机优先布局；360px 起提供双列衣橱、底部导航、全宽图片编辑和触控画笔，再逐步扩展为桌面侧栏与多列卡片。用户数据经平台身份验证，按稳定用户 ID 隔离。

## 数据与图片

`garments` 保存名称、品类、版本和可扩展 JSON 档案。季节、色系和风格为多值字段；固定标签字典位于 `config/taxonomy.ts`。个人衣橱规模下无需额外维护标签关系表；服务层独立，后续可迁移为关系表。

图片存于 R2，`assets` 记录所属用户、单品、格式与大小。服务端先校验图片签名，再写入随机对象路径；数据库批次成功前不返回成功。失败清理暂存对象。重编辑使用版本比较与交换，冲突返回 409，旧图片在新档案提交后清理。

图片接口每次授权，采用 `private, no-store`，不会由 Service Worker 缓存。草稿按用户分别保存于 IndexedDB，退出时清理。正式衣橱以云端为准；离线只保留编辑草稿。

## 识别

`workers/image-processing.worker.ts` 是单独图片线程的源文件；`scripts/prepare-runtime.mjs` 生成无开发工具注入的浏览器模块，并复制与锁文件匹配的 WASM 资源。客户端等待线程 ready 握手后才发送像素，避免异步模块初始化丢失第一条任务。

U²-NetP 提取显著主体，CLIP 量化图像编码器与预计算的 22 个文本向量匹配。类别、风格和季节均为建议；主色在蒙版范围内从原始颜色提取，更换背景与亮度不影响色系。模型顺序执行、单线程 WASM、不要求 WebGPU 或 SharedArrayBuffer。

模型分片独立位于 `public/models`，每片最多 16MiB，通过完整 SHA-256 校验。分片随当前可部署源一并保留，以确保构建和发布一致；准备脚本保留固定上游来源，后续可迁移到独立对象资源库。

## 推荐

纯函数 `features/outfits/engine.ts` 负责合法组合、季节、保暖、基础配色、风格匹配、最近穿着降权和锁定单品。服务端结合用户时区、衣橱版本和天气上下文保存每日结果。模型相似度不是准确率，单张照片不能确认材质与真实保暖程度。

## 本地兼容

正式构建始终保留 Sites 与 Cloudflare 插件。开发命令可设置 `MORI_NODE_PREVIEW=1`，在不能启动 Windows 原生 workerd 的主机上，使用 Node SQLite 和本机文件对象存储；适配器仅在 `serve` 时启用，不参与正式构建，不提供生产匿名身份回退。

`/__qa/viewport` 仅由开发中间件提供，可创建指定 CSS 宽度的同源预览框架；不随站点发布，不代表手机真机测试。
