# Yu's Mori：从照片收纳到离线衣橱

## 使用场景与范围取舍

目标是让个人能够在手机上整理已有衣物，按季节、品类、色系与风格快速查找，再手动摆出一套搭配。早期在线原型遇到手机访问限制后，交付方向调整为 HarmonyOS 离线应用。当前阶段主动去掉天气、自动搭配推荐、登录与跨设备同步，优先完成日常整理流程。

项目以个人需求驱动，借助 AI 编程工具协作实现；基础模型使用已有开源模型，不包含自研训练或准确率提升的主张。

## 核心交互

1. 从系统相册或相机选择图片，加载、取消和失败各有反馈。
2. 本地尝试抠图与粗分类，用户可裁剪、修边、调整图片和修改标签。
3. 保存后进入网格衣橱，通过多维筛选找到单品。品类为五组、23 个细分类，季节可多选。
4. 在搭配区选衣物、拖动摆放、调整大小和图层，保存搭配与预览。
5. 暂时不用的衣物进入回收站；永久删除需要再次确认，涉及搭配时额外说明影响。

## 工程问题及处理

| 问题 | 处理方式 | 实际意义 |
| --- | --- | --- |
| 推理耗时、设备能力不同 | Worker 执行、进度反馈、取消和超时，保留手动入口 | 识别失败仍能完成整理 |
| 图片与标签可能只保存一半 | IndexedDB 多表事务保存，四类图片缺一不可 | 避免出现有标签无图片的衣物 |
| 旧编辑覆盖新数据 | 保存时校验修订号 | 用户能发现并重新打开已变化的记录 |
| 删除衣物可能损坏搭配 | 同一事务重新核对引用；关联搭配需额外确认 | 防止隐式丢失搭配或产生悬空引用 |
| 新版本需要保留旧衣橱 | 增量新增存储表，不重写原有衣物表；覆盖安装 | 减少迭代中的数据丢失风险 |
| 大备份占用内存、恢复重复 | 48 MB 分卷、哈希校验、按卷事务与导入去重 | 恢复失败可重试，避免重复数据 |

手机保存的是应用私有空间中的图片副本与派生图片。回收站仍占空间，永久删除清除对应记录；相册原件和已导出的备份独立保留。图片文件统计不等于操作系统显示的整个应用占用。

## 验证方式

自动化覆盖存储、备份、筛选、引用关系、冲突及故障回滚；界面以程序生成的衣物图片做窄屏检查。Huawei Mate 80 Pro 验证系统图库进入编辑页、内置模型执行、导航返回、覆盖安装、图片占用与删除确认/取消。

不在个人照片上做永久删除试验。fake-indexeddb 事务测试与桌面浏览器预览不等于全部手机验证；真实相机流程、系统备份完整导出恢复和不同机型性能仍需继续验收。

## 后续方向

在不改变离线整理核心体验的前提下，补全真机验收、改进复杂背景抠图与照片导入体验，再按华为规则评估正式分发。跨设备同步与自动推荐属于后续独立范围，当前没有实现。
